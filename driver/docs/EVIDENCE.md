# Consolidated qualification evidence

The preceding tested snapshot is **OTTERSD 0.15 / HWRT 0.11**. Its main record
contains 334 host tests, 145 behavioral mutations, two assembly mutations and
57 qualification gates. FAT16 and FAT32 500 MiB kits have 14 additional gates
each. The user has subsequently reported smooth hardware operation; fresh
per-card log counts have not been inspected for that report, and physical
8088/5150 testing remains deferred. The machine-readable records describe
emulation qualification and are not retroactively changed by this feedback.

Working-tree documentation was clarified after the 0.15 packaging. The source
manifest in each frozen ZIP identifies the sources actually used for that release.
The 1.0.0 qualification records are generated by its separate validation run.

Developer qualification kits are driver/dist/OTTERSD.ZIP and OTTERSD.IMG.
Public 1.0.0 downloads are generated separately under driver/dist/RELEASE;
they exclude test utilities and use empty SD volumes. These outputs are
generated and ignored by Git. Original physical-card logs remain under
driver/logs/historical; old release snapshots are not kept in the repository.
EVIDENCE/QUALIFICATION.JSON records actual gate outcomes and log hashes; its
full field must be true for actual-kernel/final-image qualification. Gate logs
and coverage counters accompany the release. Build equality proves the packaged
executables match those tested; final-image checks also compare KIT binaries.

## Historical pre-OTTERSD checkpoint

The baseline physical SanDisk run passed INFO 43, TEST 278 and VERIFY 62,
with 1,777 verified sectors/transmissions and no retries. That evidence applies
to the earlier 39,888-byte binary, not this consolidation. Original hardware
logs are preserved under driver/logs/historical/resident-rw. No new physical

## Qualification scope

Required gates include host regression/coverage/behavioral mutations;
DOS 5 and 6.22 read-only CLI/EXEC/copy/empty-slot/swap; strict CRC, slow busy,
recoverable corruption/rejection/status, removal and pre-write CRC faults;
tester /RO and default-RO/marker/ERASE guards; seventeen self-exec children;
all-free-memory overwrite; fresh-boot exact verification without image writes;
and independent mtools file comparison/fsck.fat -n on the distributed image.

The single-FAT shortcut and deferred-close behavior have explicit I/O-count and
failure tests. Full commit/unmount must still detect corruption of an untouched
mirror sector; abrupt dirty remount must refuse further writes. Shared scratch
has a recovery-mutation test proving frozen expected payload survives.

Qualification does not cover physical electrical behavior, power-loss atomicity,
FCB record I/O/abnormal abort, DOS 3/4 kernels or a physical 5150. The next card
run follows MANUAL.md and must save brand/model/CID and separate logs.

The 0.6 full qualification additionally runs actual DOS XCOPY HDD-to-SD at
cluster sizes 1/8 in verified/noverify/readonly modes under both DOS kernels.
It independently checks contents, timestamps/attributes, original source files,
both filesystems, empty directories and fresh-boot read-only copying back.
The full HWRT stress/memory/persistence suite also runs with /NOVERIFY and must
report its active policy. Fast-mode host faults prove retained CRC/status/retry
and poison behavior, plus its intentional inability to detect silent writes.


The 0.7 gates additionally test actual 8086 CRC/copy/ABI and strict SD with a
three-access delayed-burst adapter under both DOS kernels. Four temporary
assembly mutations must fail independently; a resident delayed-burst profile
runs the normal DOS write/API suite. Host proofs include nonempty surplus
allocation, corrupt tails beyond logical EOF and late fragmented overwrites.
XCOPY includes SD-to-HDD readback under the writable mount as well as reboot RO.
QUALIFICATION.JSON records host/mutation counts, source and emulator hashes.

## 0.8 recovery evidence

SDRW.C is byte-identical to the 0.6 archive after a physical mounting failure was reported with
0.7. Native exhaustive CRC uses the actual C routine, while the
assembly probe/mutations now cover only retained far copying. Initialization
failure gates exercise missing CMD0, rejected CID (CMD10) and corrupt CID CRC, verified and
/NOVERIFY installs, and require matching SD snapshots through install/status/
remount/HWRT offline reports. All images must remain byte-identical. Existing
DOS API, strict/delayed transport, XCOPY, stress/memory and reboot gates remain.
The recovery build has not yet passed physical hardware qualification.

Later hardware evidence: the user reported a separately formatted FAT32 card
failing with SD error=0, stage=17, LBA=0, R1=00, token=FE, while the supplied
whole-disk image mounted successfully. The mount parser and writable preflight
are unchanged from 0.6. Format/layout or boot-sector validation is now the
leading explanation; GPT is a hypothesis pending partition inspection. The
early transfer-code regression diagnosis is withdrawn as unproven. Version
0.8 conservatively restores the known 0.6 transport and adds clearer retained
SD evidence; it does not claim to repair or support an unidentified layout.

## 0.10 unload evidence

Full qualification runs three install/unload/reload cycles for each access
policy (RO, verified RW, /NOVERIFY) under genuine DOS 5 and 6.22. The native
probe checks all saved CDS bytes, exact INT 2F restoration, total free memory,
and the largest executable DOS block against pre-install values. It also
checks open-file, current-drive, later interrupt hook and invalid MCB ownership
refusals; an unrelated allocation above the TSR survives detachment. Reload
reads previously committed file data; independent mtools and fsck validate the
result after DOS exits. One cycle unloads an already unmounted driver.

Host tests exercise versioned unload metadata, both vector words, DOS 3 versus
DOS 4+ CDS boundaries, dirty-file commit, failed mirror verification, poisoned
retry and a lost dirty session when discovery detects removal. Behavioral
mutations must expose omitted guards, lost dirty-session tracking, skipped
commit and truncated CDS restoration. These checks establish DOS memory and
filesystem behavior in emulation; physical Dune II testing remains necessary.

## 0.11 fast-mount evidence

Host tests count actual sector reads and require fast mount to avoid the full
scan while leaving the image byte-identical. Deliberate corruption proves
retained boot/geometry/FSInfo/clean/error and FAT-header guards, read CRC,
modified-sector comparisons, dirty-session commit/poison and safe unload
refusal. Mutation tests must detect omitted policy handling, header checks,
commit checks, local FAT-sector checks and policy reporting/persistence.
Genuine DOS hardware-test and unload suites run /SKIPFATCHECK under both DOS
kernels, including combination with /NOVERIFY. Versioned logs record the flag.
Physical load-time gains remain to be measured on the user's machine.


## 0.12 performance gates

The portable build adds exhaustive CRC16/varied CRC7 polynomial oracles,
mid-audit card removal/replacement guards, matching-sector invalidation tests,
and append/read boundaries for all cluster sizes from one to 128 sectors.
Four additional behavioral mutations check the new performance and safety
properties. Coverage floors remain unchanged. The complete qualifier retains
native CRC/ABI, transport faults, DOS 5/6.22 XCOPY, unload, tester stress, and
final-image gates. Exact outcomes and hashes are in each kit's
EVIDENCE/QUALIFICATION.JSON; previous research results do not substitute for
current-binary qualification. Physical testing of 0.12 remains outstanding.


## 0.13 dual-format qualification

OTTERSD 0.13 / HWRT 0.11 share one 8088-compatible driver for FAT16 and FAT32.
New host tests cover the fixed FAT16 root, two-byte FAT stores, reserved
high-word preservation, flags, format restrictions, corrupt geometry/chains,
card removal and redirector operations. Existing FAT32 protocol/fault suites
remain required. Filesystem mutations include FAT16 entry width, root-full
handling, clean flags and reserved directory fields.

The main kit's EVIDENCE/QUALIFICATION.JSON records the completed host, mutation,
DOS and packaged-image gates. The 500M and FAT16 kits each contain their own
EVIDENCE/QUALIFICATION.JSON and logs for their exact images under both DOS
kernels. The native matrix covers HWRT stress/memory and fresh-boot verify,
full unload, XCOPY with verified/unverified/read-only access, and independent
capacity/allocation checks. image.py validates both images with mtools and
fsck.fat. large_kits.py preserves the tested image while bundling evidence.

These gates qualify emulated protocol/API behavior. They do not establish
physical performance or hardware compatibility for 0.13; prior SanDisk/Intenso
results concern earlier releases. Physical 8088 testing remains deferred.

## 0.14 allocation qualification

The host suite includes stale-media allocation tests for FAT16 and FAT32.
Nonzero free clusters exercise small verified and unverified appends, EOF read
bounds, cluster crossings, truncation, gaps, explicit extension and deleted
cluster reuse. New and growing directories must clear stale entries. Injected
payload readback CRC failure must preserve the on-disk file size and poison
later writes. A command-count assertion limits a new 512-byte file append to
four sector writes (payload, two FAT copies, directory publication), rather
than adding a whole-cluster clear. Behavioral mutations check these guarantees.

Release qualification uses the full host suite and actual DOS 5/6.22 kernels,
including XCOPY with both write policies. Generated EVIDENCE/QUALIFICATION.JSON
records the completed gates and hashes for each kit. Physical timing and card
qualification for 0.14 remain separate; emulation is not a speed measurement.

## 0.15 read-cache qualification

New FAT16/FAT32 DOS-callback tests count actual sector commands and FAT lookups
for 400 KiB sequential reads. They check interleaved directories, four FAT
sectors, selective invalidation, shared overwrites and extensions, truncation
and tail reallocation with the same first cluster, backward seeks, EOF, failed
cache fills, media removal/replacement and generation wrap. Mutations remove
retention, write invalidation, wrap protection or cache guarantees and must fail
runtime assertions. Existing fresh-mutation-proof tests remain mandatory.
Archived 0.14 versus 0.15 command counts are in EVIDENCE/READCACHE.JSON.
The complete real-DOS, XCOPY, persistence, fault and exact-image gates run with
eight independent jobs. Physical throughput qualification remains separate.
